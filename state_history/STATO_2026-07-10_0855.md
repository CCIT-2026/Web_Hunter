### `start.py` — layer di output colorato

Aggiunto sistema di logging strutturato per distinguere cosa viene stampato e quando.

**Nuovi componenti:**

| Simbolo | Funzione | Visibilità |
|---|---|---|
| `→` cyan | `step(msg)` — passo in corso | sempre |
| `✓` verde | `ok(msg)` — completato | sempre |
| `⚠` giallo | `warn(msg)` — avviso non bloccante | sempre |
| `✗` rosso | `err(msg)` — errore su stderr | sempre |
| `[dbg]` magenta | `dbg(**kwargs)` — dump variabili compatto | solo `--debug` |

**`run_cmd(cmd, *, capture, cwd, shell)`** — wrapper subprocess:
- Default: sopprime stdout/stderr del tool
- `--verbose`: lascia fluire stdout/stderr
- `capture=True`: cattura sempre per uso logico; stampa con `--verbose`
- `--debug`: logga il comando lanciato (`$> ...`), mai l'output

**`run_interactive(cmd)`** — comandi approvati dall'utente: output sempre visibile.

**Contratto flag:**

| Flag | Messaggi colorati | Stdout tool | Dump variabili |
|---|---|---|---|
| (nessuno) | ✓ | ✗ | ✗ |
| `--verbose` | ✓ | ✓ | ✗ |
| `--debug` | ✓ | ✗ | ✓ |
| `--debug --verbose` | ✓ | ✓ | ✓ |

**Bonus:** se build fallisce senza `--verbose`, appare hint automatico `⚠ Riavvia con --verbose per i dettagli del build.`

`--verbose` e `--debug` aggiunti come argomenti espliciti al parser (prima erano silenziosi/ignorati).

### Bug A — critico (`sqlmap_runner.py:28`, `ghauri_runner.py:27`)

`settings.get("target_url", fallback)` non attiva mai il fallback perché la chiave `"target_url"` esiste nel dict (con valore `""`). URL risultante: `"/api/login"` → sqlmap fallisce silenziosamente (rc=1, nessun match su stdout, `status: "completed"`, `findings: []`).

```python
# Attuale — sbagliato
target_base = self.settings.get("target_url", _TARGET_URL).rstrip("/")

# Fix da applicare
target_base = (self.settings.get("target_url") or _TARGET_URL).rstrip("/")
```

### Bug B — medio

`/api/store/<int:article_id>/buy` viene passato letteralmente come URL. I caratteri `<>` la rendono invalida. Fix: sostituire `<int:x>` → `1`, `<path:x>` → `test`, `<x>` → `test` prima di costruire la URL.

### Bug C — minore

Endpoint con solo path params (es. `article_id`): né `body_params` né `query_params` matchano → nessun `--data`, nessun marker `*` nella URL → il parametro non viene mai testato da sqlmap.
